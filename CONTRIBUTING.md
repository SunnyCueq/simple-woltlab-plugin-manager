## 🤝 Willkommen!

Vielen Dank, dass du zum **Simple WoltLab Plugin Manager** beitragen möchtest! Dieses Projekt ist Open Source und Community-getrieben. Jeder Beitrag ist willkommen.

## 📋 Wie kann ich beitragen?

### 1. 🐛 Fehler melden

**Hast du einen Fehler gefunden?**

1. Prüfe zuerst, ob das Problem bereits als [Issue](https://github.com/SunnyCueq/simple-woltlab-plugin-manager/issues) existiert
2. Falls nicht, erstelle ein neues Issue mit:
   - **Beschreibung:** Was ist das Problem?
   - **Schritte zur Reproduktion:** Wie kann man den Fehler nachvollziehen?
   - **Erwartetes Verhalten:** Was sollte passieren?
   - **Tatsächliches Verhalten:** Was passiert stattdessen?
   - **Umgebung:** Betriebssystem, PHP-Version, etc.

### 2. 💡 Feature-Vorschläge

**Hast du eine Idee für eine neue Funktion?**

1. Prüfe, ob bereits ein ähnliches [Issue](https://github.com/SunnyCueq/simple-woltlab-plugin-manager/issues) existiert
2. Falls nicht, erstelle ein neues Issue mit:
   - **Beschreibung:** Was soll die neue Funktion machen?
   - **Use Case:** Warum ist das nützlich?
   - **Beispiel:** Wie würde es verwendet werden?

### 3. 📝 Code beitragen

**Möchtest du Code beitragen?**

#### Schritt 1: Repository forken

1. Klicke auf "Fork" oben rechts auf der GitHub-Seite
2. Klone dein geforktes Repository:
   ```bash
   git clone https://github.com/DEIN-USERNAME/simple-woltlab-plugin-manager.git
   cd simple-woltlab-plugin-manager
   ```

#### Schritt 2: Branch erstellen

Erstelle einen neuen Branch für deine Änderung:

```bash
git checkout -b feature/meine-neue-funktion
# oder
git checkout -b fix/fehlerbehebung
```

**Branch-Namen:**
- `feature/` - für neue Features
- `fix/` - für Fehlerbehebungen
- `docs/` - für Dokumentationsänderungen
- `refactor/` - für Code-Verbesserungen

#### Schritt 3: Änderungen machen

- Mache deine Änderungen
- Teste sie gründlich
- Stelle sicher, dass alles funktioniert

#### Schritt 4: Committen

**Wichtig:** Verwende klare, beschreibende Commit-Messages:

```bash
git add .
git commit -m "feat: Neue Funktion für Plugin-Validierung hinzugefügt"
```

**Commit-Message-Format:**
- `feat:` - Neue Funktion
- `fix:` - Fehlerbehebung
- `docs:` - Dokumentation
- `refactor:` - Code-Verbesserung
- `test:` - Tests
- `chore:` - Wartungsarbeiten

#### Schritt 5: Push und Pull Request

```bash
git push origin feature/meine-neue-funktion
```

1. Gehe zu deinem geforkten Repository auf GitHub
2. Klicke auf "Compare & pull request"
3. Beschreibe deine Änderungen klar
4. Warte auf Review

## 🤝 Welcome!

Thank you for wanting to contribute to the **Simple WoltLab Plugin Manager**! This project is open source and community-driven. Every contribution is welcome.

## 📋 How can I contribute?

### 1. 🐛 Report Bugs

**Found a bug?**

1. First check if the issue already exists in [Issues](https://github.com/SunnyCueq/simple-woltlab-plugin-manager/issues)
2. If not, create a new issue with:
   - **Description:** What is the problem?
   - **Steps to reproduce:** How can the bug be reproduced?
   - **Expected behavior:** What should happen?
   - **Actual behavior:** What happens instead?
   - **Environment:** Operating system, PHP version, etc.

### 2. 💡 Feature Suggestions

**Have an idea for a new feature?**

1. Check if a similar [Issue](https://github.com/SunnyCueq/simple-woltlab-plugin-manager/issues) already exists
2. If not, create a new issue with:
   - **Description:** What should the new feature do?
   - **Use case:** Why is this useful?
   - **Example:** How would it be used?

### 3. 📝 Contribute Code

**Want to contribute code?**

#### Step 1: Fork Repository

1. Click "Fork" at the top right of the GitHub page
2. Clone your forked repository:
   ```bash
   git clone https://github.com/YOUR-USERNAME/simple-woltlab-plugin-manager.git
   cd simple-woltlab-plugin-manager
   ```

#### Step 2: Create Branch

Create a new branch for your changes:

```bash
git checkout -b feature/my-new-feature
# or
git checkout -b fix/bug-fix
```

**Branch naming:**
- `feature/` - for new features
- `fix/` - for bug fixes
- `docs/` - for documentation changes
- `refactor/` - for code improvements

#### Step 3: Make Changes

- Make your changes
- Test thoroughly
- Ensure everything works

#### Step 4: Commit

**Important:** Use clear, descriptive commit messages:

```bash
git add .
git commit -m "feat: Add new plugin validation feature"
```

**Commit message format:**
- `feat:` - New feature
- `fix:` - Bug fix
- `docs:` - Documentation
- `refactor:` - Code improvement
- `test:` - Tests
- `chore:` - Maintenance

#### Step 5: Push and Pull Request

```bash
git push origin feature/my-new-feature
```

1. Go to your forked repository on GitHub
2. Click "Compare & pull request"
3. Describe your changes clearly
4. Wait for review
